# Сайт Safety Evals и сертификаты

Готовый статический сайт для GitHub Pages: исходная страница курса, карусель с 20 менторами, проверка кода и отдельный URL каждого сертификата. HTML/CSS можно править без сборщика. Python нужен только для создания страниц сертификатов; GitHub Actions делает это автоматически.

## Разместить через браузер GitHub

1. Создайте **публичный** репозиторий, например `safety-evals`, с основной веткой `main`.
2. Распакуйте ZIP. Загрузите **содержимое** папки сайта в корень репозитория, чтобы `index.html`, `data`, `assets`, `scripts`, `requirements.txt` были на верхнем уровне. Скриншоты из папки QA загружать необязательно.
3. Важно: скрытую папку `.github` веб-загрузка иногда пропускает. Проверьте, что в репозитории есть `.github/workflows/pages.yml`. Если нет: **Add file → Create new file**, имя `.github/workflows/pages.yml`, скопируйте содержимое одноимённого файла из архива, **Commit changes**.
4. Откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**.
5. Во вкладке **Actions** выберите **Build and deploy Pages → Run workflow → main → Run workflow**. После зелёного запуска адрес сайта появится в Settings → Pages: `https://USER.github.io/REPO/`.

Workflow сам подставляет адрес репозитория в canonical и OG-теги. Работает и с путём `/REPO/`. На личном репозитории `USER.github.io` путь будет корневым. Если основная ветка называется иначе, замените `main` в `.github/workflows/pages.yml`.

## Как изменить курс

Откройте `index.html` → значок карандаша → поменяйте текст → **Commit changes**. Сохранены тексты, менторы, биографии и программа оригинала; кнопка заявки на завершившийся курс и телефон удалены по просьбе Юли. Комментарии в HTML отмечают шапку, менторов, описание и нижний блок. Можно целиком удалить верхний `header` и нижний `footer`, если они не нужны. Не удаляйте `assets/course.js`, если нужна карусель и открытие биографий. Дополнительные стили — `assets/site.css`; оригинальные — `assets/css/style.css`; фото — `assets/images/mentors/`.

Оставшиеся ссылки на Telegram, документы и прочие разделы ведут на исходные ресурсы monoid. Перед публикацией проверьте даты, контакты и название организатора. Организатор сертификата сейчас «Моноид»; для изменения отредактируйте `scripts/build.py` и `assets/certificate.js` (LinkedIn).

## Добавить выпускника в веб-интерфейсе GitHub

Единый источник данных — `data/graduates.csv`. Заголовок:

```csv
first_name,last_name,course,date,code,example
```

1. Получите новый случайный код. Можно локально выполнить `python3 scripts/new_code.py`. Либо откройте на опубликованном сайте `code-generator.html`: кнопка использует `crypto.getRandomValues`, ничего не отправляет на сервер. Копируйте код, не переиспользуйте его для другого человека.
2. Откройте в GitHub `data/graduates.csv` → карандаш. Добавьте строку: имя, фамилия, курс, дата `ГГГГ-ММ-ДД`, новый код, `false`. Если в поле запятая, заключите поле в двойные кавычки; кавычку внутри удвойте. Сохраните заголовок и кодировку UTF-8.
3. Нажмите **Commit changes**. Дождитесь зелёного Actions. Пример URL: `https://USER.github.io/REPO/certificate/КОД/`.
4. Найдите запись через «Проверить сертификат», откройте её и передайте выпускнику ссылку. На странице есть LinkedIn, копирование ссылки, PNG и печать в PDF (в диалоге браузера выберите «Сохранить как PDF»).

Три исходные записи — **демонстрационные**, с `example=true`, маркировкой «ПРИМЕР» на странице и PNG. Удалите их строки перед реальным выпуском. Не меняйте `true` на `false` для тестовых имён. Фото настоящего списка можно прислать ассистенту Влада — внесём данные.

Удаление строки и последующий успешный запуск Actions удаляют страницу из новой версии сайта. Старые скачанные файлы и кеши сторонних сайтов не отзываются. Любая информация CSV публикуется открыто: размещайте только согласованные имя, курс, дату и код. Проверка кода сверяет запись с опубликованным реестром; криптографической подписи и независимой аккредитации нет. Коды содержат 192 бита случайности, но доступ по ссылке публичный. LinkedIn может кешировать OG-превью; после обновления используйте LinkedIn Post Inspector.

## Локальная сборка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
# Для генерации PNG нужен системный DejaVu Sans (Ubuntu: fonts-dejavu-core).
.venv/bin/python scripts/build.py --base-url http://localhost:8000
python3 -m http.server 8000 --directory _site
```

Откройте `http://localhost:8000`. `_site` генерируется заново при каждой сборке, вручную его не редактируйте. Неверные даты, пустые поля и повторные/небезопасные коды останавливают сборку. В архиве только исходники, Pages создаст HTML и PNG из CSV. `code-generator.html` также копируется в сборку.

## Источники и права

Страница курса, CSS, иллюстрация и фотографии скопированы с https://monoid.ru/events/course-safety-evals-2026 (9 ноября 2026). Используются системные шрифты оригинала; внешних шрифтов нет. Аналитика исходного сайта удалена. Поведение карусели и окон биографий реализовано отдельным небольшим скриптом.

**Тексты и фото принадлежат их правообладателям. Если курс не ваш, требуется согласие организаторов на публикацию копии и выдачу сертификатов от их имени.** Файл передаётся Юле для редактирования и размещения её ботом.

Страницы https://lensacademy.org/certificate/VUxwbDkgog1fc02CSNmlZg и https://bluedot.org/certification?id=rec3EixGSgPrb9pqO изучены как функциональные примеры: имя, курс, дата, уникальный код, публичная ссылка и проверка записи. Их брендинг и персональные данные в реестр не копировались.

Коды и полный список выпускников открыты в CSV и registry.json. Непредсказуемость кода предотвращает случайные совпадения, но не делает его секретом. Коды берите только из генератора. Проверяющий должен сверять домен с официальным адресом организатора: копия сайта на чужом домене не является подтверждением. Для демонстрационных записей добавление в LinkedIn отключено.
